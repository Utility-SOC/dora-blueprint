=== two real bugs found via this run, not assumed from a clean pipeline ===

1. `run-drill.sh` extracts the raw drill record from the workflow pod's logs by grepping for
   a line starting with `{"drill_id"`. The workflow template's own script reassigns that
   record through `jq` whenever `t_detect` is captured -- which is the normal, successful-
   detection case -- and plain `jq` pretty-prints, putting the opening brace alone on its own
   line. Every detected drill was silently handing `enrich.py` an empty string. Confirmed via
   a real run producing zero grep matches (`kubectl logs ... | grep -c '^{"drill_id"'` = 0).
   Fixed with `jq -c` (drills/templates/ns-restore-workflowtemplate.yaml).

2. `open-incident.py` (like `enrich.py`) runs host-side, invoked by `run-drill.sh` on appserv
   *after* the workflow pod has already exited -- unlike Phase 9's Grafana-detection-poll,
   which runs *inside* the pod. It first tried GLPI's in-cluster Service DNS name
   (glpi.glpi.svc.cluster.local), which appserv has no route to. Confirmed via a real
   `socket.gaierror: Temporary failure in name resolution` from a live drill run. Fixed by
   using the same LAN port-forward address (192.168.1.106:9085) a human operator already
   relies on for every other service in this repo.

Both fixes: commits 97cc98a, 9edd02a.
